# Feature inventory — the Great Merge (Phase 0)

The client's feature set lives in the extension (`tools/ext/t2r-ext.c`, a unity build that
`#include`s 135 sibling modules). The Great Merge ports each **feature** into `mod/` source —
the C is the behavioural reference, not the code being moved. This file is the control surface:
one row per module, its domain, its dependency footprint, its `t2r-*.txt` toggles and where the
mod already overlaps.

Generated by `mod/scripts/gen-features.py` from the ext's include list + `tools/ext/GENERATED.md`.
Domain / overlap / status maps are curated by hand. Re-run after the ext's module list changes.

**Legend** — `Pri`: P1 first … P5 last. `Deps`: mechanism tags the module uses (`net`, `audio`, `widget`, `camera`, `pad`, `hook`) plus `data` when it needs generated headers. `Toggles`: count of `t2r-*.txt` switches the module reads. `Mod overlap`: existing mod code the port should extend. `Status`: `not started` / `in progress` / `ported` / `dropped`.

**Port notes.** The join-in-progress logic inside `t2r-ext.c` is now partly native:
`net/online/jip-report.{hpp,cpp}` owns the 0xE3 clock report (cadence, clock flags, team /
lives, AFK trailer, bounded RPC, generation check, backoff) and consumes the 0xE5 reply's
server settings, including the no-AFK test-server flag. Roster merge, in-match team swap,
late-join query and ghost peer reaping stay in the ext and are called out as TODO gates in
that module. The requeue flag (0x20) is now sent while `t2r-no-requeue.txt` is absent; the
ticket check / auto-search / WAITING FOR PLAYERS... label live in `net/online/requeue.*`.

`net/online/requeue.*` ports the daemon 0xBC ticket poll (bounded worker through
`net::daemon::Rpc`), the match-end arm (now via the shared `net::match::liveness` latch), the
MP-menu settle + page push and the status-label swap. Party leadership / follow (`FrInParty` /
`me_leader`) and the party-follow search gate (`g_pqAuto`) are now native via `net::friends13`
(`IsMember()` / `NoteAutoPush()`). Honest gates: the exact end byte / MatchSubstate, `g_kickMs`
and the post-match screen latches (`clan13x` / `clan-postmatch` / clan event / GEAR UP nav) are
unported; a stable top page over the settle window stands in for the screens and the ext still
owns the latches while it is the bridge.

`net/social/friends13.*` + `net/social/friends-state.*` port the whole in-game FRIENDS / PARTY
feature: the async daemon 0xD8/0xD9 state+action RPC (bounded worker, poll cadence 3 s panel /
2.5 s party / 15 s menu, an action first and its reply becoming fresh state), the panel page with
its rows / typing / badge / leader+ready party list, the friend-request + party-invite cards (plain
toasts when `t2r-no-friend-toast.txt` or the widgets are absent), the P / pad button and lobby
decorations, the notice-c cross-feature toasts and dedupe, and the party ready / follow-the-leader
+ search gate (`InParty` / `IsMember` / `SearchGate` / `NoteAutoPush`) now used by requeue and
`net-gui2.cpp`. The pure JSON/state core is a standalone module, so it can be tested without a game.
`net/match/match-liveness.*` is the shared once-per-frame match-end latch (ext `g_wasLive`): it
supplies `MatchEndHold()` to requeue and `Live()` / `MatchEndHold()` to friends13, so all consumers
see one read of the mod's match phase. Honest gates: the rank table (0xBF / `rankbadge.c`), the raw
lobby object / `kPartyStatus` / `g_srchTab` / `g_srchName` producers, exact `menu-*` pad bindings,
mouse-over click nav and the card's per-widget keyframes are not ported; widget writes are inert
when the defs are absent and the ext still owns those producers while it is the bridge. The two
opt-outs are `t2r-no-ingame-friends.txt` and `t2r-no-friend-toast.txt`.

`net/game/net-direct.*` ports the Steam-helper loopback socket, [06]/[07] hello/ack, the
[05] ping/pong/message wire, the 800 ms cross-path dedupe ring, direct RTT EWMA gating and
the send/recv integration (`net::session::SendEventRaw` outgoing, `HandleState` incoming).
Helper discovery uses `net::transport::RelayEndpoint()` (the mod's `kNetCtx +0/+0x10`). Honest
gates: the ext's melee-critical opcodes have no mod `NEVT_*` equivalents, so the eligible set
is the mod's melee / hit events (`NEVT_PLAYER_MELEE_ATTACK`, `NEVT_TAKE_DAMAGE`) with the rest
of the ext set still on the ext's own path; the RTT baseline is the per-peer `PingMs()` instead
of `g_psRtt[]`, and the helper's single "ext address" registration means the ext copy must be
retired before this path is exercised.

`engine/pad.{hpp,cpp}` now ports the whole virtual pad from `padinject.c`: virtual button presses
and sticks, command-bit learning, bounded delivery, the raw melee / dodge / stick readers and the
AFK activity stamp. The ext's hardcoded call-site RVAs and near-image thunks are replaced by a
rel32 call-site scan + safetyhook mid-hooks; the pinned function prologues are preferred when they
match and the unfocused-window byte stays version-guarded. The dev-bot, melee-pace and QTE
*consumers* of the API are still unported, and the call-site scan needs a live exe to verify.
